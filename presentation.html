Relational Database Schema & Data Integrity
Normalized MySQL database architecture ensuring relational consistency and transaction safety across all operations.

🗄️
Core Relational Entities
Table Architecture
Table Name Primary Key / Identifier Core Relationships & Role
cranes id (INT AUTO) Fleet master data, capacity, model, status
operators id (INT AUTO) Operator profile, license, link to users
riggers id (INT AUTO) Rigger profile, experience, link to users
sites id (INT AUTO) Project location, party, supervisor link
gang_assignments id (INT AUTO) Pairs crane_id, operator_id, rigger_id
deployments id (INT AUTO) Links Gang or Crane to site_id with dates
logbook_entries id (INT AUTO) Daily log sheet records, meter readings, hours
🛡️
Data Validation & Consistency Rules
ACID Rules
  • Referential Integrity: Foreign key constraints guarantee that logbook entries cannot be created without valid Crane and Site records.
  • Unique Constraint Protection: Prevents duplicate attendance or conflicting gang assignments for the same operator on a single date.
  • Audit Trail Fields: Every record tracks created_at, updated_at, and originating user_id.
  • Connection Pooling: High-throughput MySQL connection pool manages concurrency under peak field check-in hours.
Security: All SQL queries utilize parameterized statements to completely prevent SQL injection attacks.
